# Dubplate threat model

This document describes the implemented security boundaries and their limits. Dubplate runs on a computer controlled by its owner, connects to Discord, and executes third-party media tools. It is not a hardened sandbox for hostile media sites or malware running as the same Windows user.

## Assets and trust boundaries

| Boundary | Assets and trust decision |
| --- | --- |
| Discord and music sites → bot utility process | Slash-command inputs, URLs, titles, uploader names, playlists and media are untrusted. The bot token authorizes the Discord application. Discord users must share the bot’s voice channel to control it. |
| Renderer → preload → main | The renderer has no Node API. Its explicit preload methods send validated IPC to the one local top-level window. Main owns settings, native dialogs, secrets, lifecycle and managed downloads. |
| Main ↔ bot utility process | A MessagePort carries commands and events. The token crosses this boundary in memory. Audio, Discord REST/gateway and media extraction run in the utility process. Process isolation protects UI availability; it is not an operating-system security sandbox. |
| Official release servers → managed executables | Main downloads only from fixed HTTPS hosts, checks every redirect and verifies SHA-256 before executing or installing a managed tool. Bundled Node is verified at build time and before use. |
| Local disk → main and utility process | Settings are validated and migrated. The token is DPAPI-encrypted through Electron safeStorage. Managed executables are hashed against saved verification records. User-selected ffmpeg and PATH are trusted local software choices. |
| Source and build tooling → public installer | Exact dependency versions and the lockfile define dependencies; Actions are pinned to commit hashes. Windows jobs build NSIS, optionally sign the outer installer in an isolated job, and publish only the installer and SHA256SUMS. Signing credentials are optional and never enter the build job. |

Main makes no Discord or media HTTP requests and provides no HTTP control server. Runtime communication uses Electron IPC and MessagePorts. The renderer can request HTTPS artwork only from the fixed thumbnail hosts enforced by `desktop/main.js`; remote document navigation, popups, webviews and permissions are denied. External browser links are generated from a short allowlist.

## Controls and regression coverage

| Threat | Implemented control | Code and tests |
| --- | --- | --- |
| A Discord user requests LAN, local-file or option-like input | Parse HTTP(S) URLs, reject IP literals (including normalized decimal/hex forms), localhost, userinfo, non-default ports and domain-suffix tricks. Match music domains exactly or by dot suffix. Search phrases receive a fixed `ytsearch1:` prefix. The same core policy handles the desktop Add box. | `src/util/validation.js`, `src/player/ytdlp.js`; `test/allowlist.test.js`, `test/validation.test.js`, `test/core.test.js` |
| Someone invites the bot into another server | Once configured, enforce one guild on ready, gateway recovery and every guild-create event; leave other guilds and log the action. While unconfigured, the first newly joined guild is selected, while pre-existing memberships remain a deliberate fallback list. | `src/core/BotCore.js`; `test/core-setup.test.js` |
| Shell injection or unintended ffmpeg network access | Child processes use executable-plus-argument arrays with `shell: false`. A literal `--` separates yt-dlp options from user input. ffmpeg accepts only the `pipe` protocol. yt-dlp receives fixed flags and ignores external configuration. | `src/player/processes.js`, `src/player/ytdlp.js`; `test/allowlist.test.js`, `test/pipeline.test.js`, `test/processes.test.js` |
| Renderer compromise obtains arbitrary main-process capabilities | Context isolation, sandbox, no Node integration, strict CSP, explicit preload methods, exact sender/main-frame/file-URL checks, and field/type/range validation on every handler. No generic IPC invocation or arbitrary external URL API. Changing the ffmpeg executable requires a native file dialog. | `desktop/main.js`, `desktop/preload.cjs`, `desktop/ipc-validation.js`; `test/desktop-security.test.js`, `test/renderer.test.js` |
| Track text or log entries become script or HTML | Untrusted strings are assigned as text. No remote scripts, inline scripts or eval. Artwork requests are restricted separately from text rendering. | `desktop/renderer/index.html`, `desktop/renderer/app.js`, `desktop/main.js`; `test/renderer.test.js` |
| The token leaks through settings, UI snapshots or logs | Only safeStorage ciphertext is persisted; insecure storage is refused. UI receives configured status and public bot identity, never the saved token. Known tokens and token-like fields are redacted before ring-buffer/file output. | `desktop/secrets.js`, `desktop/logs.js`, `desktop/main.js`, `src/util/log.js`; `test/desktop-security.test.js`, `test/startup.test.js` |
| Setup reads unrelated clipboard contents or a test request executes a user-selected file | Clipboard reads require the explicit Paste capability and an active user gesture; a token shape check precedes Discord validation. Voice testing accepts only a channel ID through IPC. Main supplies a fixed bundled original WAV and verified tool paths; the same pipe-only PCM/Opus path plays it without a local server or extractor bypass. | `desktop/preload.cjs`, `desktop/ipc-validation.js`, `desktop/main.js`, `src/core/BotCore.js`, `src/player/ytdlp.js`; `test/desktop-security.test.js`, `test/core-voice.test.js`, `test/renderer.test.js` |
| A download redirects to a hostile host, grows without bound, or stalls | HTTPS with certificate verification, exact fixed download hosts, a five-redirect limit checked at every hop, byte limits, inactivity and overall timeouts, and exclusive temporary files. Asset URLs are reconstructed from validated official release tags. | `desktop/downloads.js`, `desktop/binaries.js`; `test/downloads.test.js`, `test/binaries.test.js` |
| A partial or changed tool executes | yt-dlp is verified against its official release’s SHA2-256SUMS. Gyan’s official GitHub ffmpeg ZIP is verified against the release asset SHA-256 and compared with Gyan’s separate checksum when reachable. ZIP extraction checks paths, sizes and CRC. Installation verifies, atomically replaces, version-checks and rolls back on failure. Main and core hash managed executables again before execution, including bundled Node. | `desktop/binaries.js`, `desktop/downloads.js`, `src/util/integrity.js`, `src/player/ytdlp.js`; `test/downloads.test.js`, `test/binaries.test.js`, `test/core-integrity.test.js` |
| Concurrent setup downloads lose verification records, or manual recovery runs an unchecked file | Per-tool download locks allow independent transfers; a shared installation/metadata lock preserves both records. Manual yt-dlp selection is copied into private staging and must match an official release checksum or a saved verified release before execution. Failed preparations keep verified successes available for retry. | `desktop/binaries.js`, `desktop/setup-tools.js`; `test/binaries.test.js`, `test/setup-tools.test.js` |
| Corrupt settings crash the UI or invalid settings reach the core | Schema migration, shared numeric limits, typed patches, atomic writes and visible fallback-to-default notices. Renderer cannot set internal settings fields. | `desktop/settings.js`, `src/util/config.js`, `desktop/ipc-validation.js`; `test/desktop-security.test.js`, `test/validation.test.js` |
| Playback leaves runaway processes or a crash takes down the UI | A supervised utility process, bounded capture/output limits, playback stall watchdog, Windows process-tree termination, Linux process groups, graceful shutdown, and restart backoff. Queue limits bound track accumulation. | `desktop/supervisor.js`, `src/player/processes.js`, `src/player/GuildPlayer.js`; `test/processes.test.js`, `test/player.test.js`, `test/pipeline.test.js` |
| Old bot events change a replacement bot's settings, or crash recovery restarts a newer worker | Guild persistence verifies current token and configuration ownership when the queued write runs. Worker lifecycle operations are ordered and recovery checks current lifecycle intent after cleanup. Native file selection and app reset coordinate with background preparation. | `desktop/main.js`, `desktop/supervisor.js`, `desktop/worker.js`; `test/main-lifecycle.test.js`, `test/desktop-lifecycle.test.js` |
| Private files or unrelated binaries enter a release | Explicit package file selection, ignored runtime/user data, secret scanning, source-hygiene tests, and a release artifact allowlist. yt-dlp and ffmpeg are downloaded after install; neither is shipped in source or NSIS. Only the verified Node runtime is bundled. | `.gitignore`, `electron-builder.yml`, `scripts/scan-secrets.js`, `.github/workflows/release.yml`; `test/public-release.test.js` |

## Residual risks

- **Redirects and DNS rebinding:** yt-dlp 2026.08.19 has no general redirect-host allowlist option. The initial URL and returned webpage URLs are checked, but the extractor’s internal redirects, manifests and media CDN requests are not confined by Dubplate’s music-host list. Allowlisted DNS names can also resolve or rebind to private addresses. ffmpeg’s pipe-only protocol restriction does not constrain yt-dlp’s own network requests. Use trusted music sites and Discord users; network-level egress controls are required for a stronger LAN boundary. Adding a domain in Settings expands trust to all its subdomains.
- **Third-party code:** Electron, Discord libraries, native DAVE, Opus, Node, yt-dlp and ffmpeg can have vulnerabilities. A checksum establishes correspondence to a trusted release, not that the release is safe. A compromised upstream account or build pipeline can publish a malicious file and matching checksum. Gyan checksum-mirror outages fall back to its official GitHub release digest, never to an unchecked download.
- **Local attackers and races:** Malware running as the same user can alter the application, verification records, PATH or selected ffmpeg, use DPAPI as that user, inspect process memory, or race path-based verification and execution. Administrator access is stronger still. Checks detect ordinary on-disk tampering; they are not code signing or a local privilege boundary. Tokens remain in main/utility memory while running and briefly in the entry field while being entered.
- **Distribution and signing:** Builds are unsigned by default. Optional [Azure Artifact Signing](signing.md) signs only the outer Setup executable, after the build and before checksums; the contained application and uninstaller remain unsigned. Configured signing failures block publication. Signing identifies a publisher, not safe behavior, and SmartScreen can still warn. SHA256SUMS detects transfer corruption or mismatched artifacts; an attacker controlling the release page can replace both. Compromised signing credentials can authorize malicious releases. There is no automatic application updater.
- **Privacy:** Discord and requested music services receive network requests and associated metadata. Artwork providers receive image requests. Logs can retain track names and other playback metadata for up to seven days within a file-count/size cap. Token redaction cannot guarantee removal of every possible encoding or fragmentation of a secret, and it does not sanitize unrelated personal data.
- **Legacy `.env` erasure:** Import reads a folder selected by the owner. Overwriting and deleting the old file cannot guarantee erasure from SSD wear leveling, backups, cloud sync or snapshots. Reset an exposed Discord token rather than relying on file deletion.
- **Availability:** A trusted site can be slow or unavailable; extraction can consume CPU and memory despite queue, output and time bounds. Discord outages and API limits remain outside the app’s control. The utility process is isolated from UI hangs, but operating-system resource exhaustion can affect both.
- **Discord application ownership:** Guild command registration replaces that application’s guild-command list. Setup recommends a dedicated private Discord application. Reusing an application can disrupt another bot that shares it.
- **First-invite race:** Initial unconfigured setup uses the first new guild-create event, not proof that the local app owner owns that guild. Someone who knows the application ID and can invite it elsewhere could win that race. Check the displayed server name before continuing. Optional private-bot hardening reduces unauthorized invitations; the configured-guild policy prevents later invitations from expanding access.

Media integration tests open a temporary loopback HTTP fixture and use an explicit test-only backend; production IPC/settings cannot choose it. The user-facing voice test instead reads the bundled original tone into a pipe and checks effective channel permissions, fullness and connection timeout. Unit tests inject a voice transport; packaged smoke verifies native DAVE and both PCM/Opus paths. These checks do not prove live Discord negotiation, every extractor site, or audio actually heard by another user. The delivery report must distinguish local checks from authenticated end-to-end verification.

## Maintenance

Changes to network requests, URL policy, preload/IPC, binary selection, secrets or packaging require corresponding tests and an update to this document. Dependabot proposes dependency and GitHub Actions updates weekly. Report vulnerabilities privately as described in [SECURITY.md](../SECURITY.md).
